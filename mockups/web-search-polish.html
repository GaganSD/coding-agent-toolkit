pi-web-search polish: P0 + P1

Mockups only. These cover one PR: the search row, removing /reload, the control panel, onboarding and errors. README and docs are out of scope, and so is the quality-signals line. Every panel uses the Slate /shortcuts frame from PR 174 so all extensions share one look.

P0The search row

The model still receives the same text, under the same budget. Only the human view changes: what was found comes first, and how it was found moves to the expanded footer.

P0No more /reload

Before
Classifier pinned: openrouter/~typesafe/jev-latest.
Saved to ~/.pi/agent/web-search.json — run /reload
to apply.

Saved parallel API key.
Run /reload so Parallel MCP picks up the new header.
After (panel message line)
✓ Saved — applies to the next search

✓ Parallel connected — higher limits on

▲ GITHUB_TOKEN is set and still wins over this key

Settings are read on every search, which already happens. When the Parallel key changes, the MCP server registers again, so nobody has to reload. The only time a reload might remain is a host limit on re-registering MCP. In that case the panel should offer R Reload now instead of printing an instruction.

Scope of the single PR (P0 + P1)

  • Search row: renderCall, renderResult (collapsed and expanded), staged onUpdate progress, the cached tag, and duration in details.
  • No reload: re-register Parallel MCP when its key changes, and remove "run /reload" from every normal path.
  • Panel: replace the select menu tree with one ctx.ui.custom panel built on the shared frame. Cover search providers and their order, thorough, results, accounts (paste, check, save, remove), classifier, and the broken-config fix.
  • Onboarding: drop the first-run select in favour of one dim line. The first /web-search opens on Accounts.
  • Errors: human-facing lines say what happened and the next step. Model-facing errors don't change.
  • Out of scope: README and docs (you're doing those), quality signals, and new providers.
