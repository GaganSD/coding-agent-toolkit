Slate control panels: focus and alignment polish

Mockups only. This is the Slate version of the polish shipped in pi-web-search PR 183: the same two-pane focus model, the same fixed detail layout, and the same data-built section rows. Scope is /shortcuts and /theme. The Slate picker frame stays canonical; the PR will note the web-search vendor resync.

One interaction model. Left focus: ↑↓ moves, → or Enter opens, Esc closes. Right focus: ↑↓ moves the options, Enter or Space applies, ← or Esc returns to the same left row. Moving the cursor never saves. The unfocused pane keeps a dim › marker, so focus is always visible. Footer hints come from the same action table that handles input.

What changes

ProblemBeforeAfter
NavigationOne cursor. /shortcuts has a detail pane but no way to focus it. /theme changes palettes with ←→ while the cursor stays on the theme.Left and right focus. The left row stays selected when focus moves right; its marker dims. Esc on the left closes; Esc on the right goes back.
Right paneNo stable right-pane contract. /shortcuts mixes detail, shortcut and status lines; /theme is only a palette viewport.Title, description, blank line, options, status. The same lines stay in the same places in both focus states; only the cursor and highlight change.
AlignmentStatus text starts at the pane edge. Wide keycaps and long labels can move it.One fixed name and value column per pane; status text stays in the right pane. visibleWidth/truncateToWidth keep glyphs in place. Status lines align with option names.
Repeated labels/shortcuts sections live in a hard-coded map. Every Catppuccin row repeats the Catppuccin prefix.Sections come from the action data: ── Layout, ── Pickers, ── Display. Themes group the repeated family and tone: ── Catppuccin · Light, ── Catppuccin · Dark, ── Other.
Wording“PID display”, “Effort border color”, “Density”, “Composer metadata”, “Palettes 4/16”.“Process ID”, “Effort border”, “Spacing”, “Composer details”. Short plain verbs: Open, Choose, Back, Close, Save, Remove.
Tiny terminalsThe title and a hint can crowd out the active row.The active choice, input or status wins the available lines. Hints are dropped before they are.

Rows are assembled from cells measured with visibleWidth and cut with truncateToWidth. Wide CJK or emoji labels cannot push the glyph column out; they get an ellipsis. The status glyph and its text are one cell, so they always move together.

10 · Sections come from data

Before: hard-coded in the panel
const SECTIONS = {
  sidebar: "Layout",
  prompts: "Pickers",
  pid: "Display",
};
After: carried by the row data
{ id: "sidebar", section: "Layout", ... }
{ id: "prompts", section: "Pickers", ... }
{ id: "pid", section: "Display", ... }

{ label: "Latte", family: "Catppuccin",
  section: "Catppuccin · Light", ... }
{ label: "Mocha", family: "Catppuccin",
  section: "Catppuccin · Dark", ... }

The list builder inserts a ── Section whenever the section changes. Shortcut sections move into SHORTCUT_ACTIONS; theme labels, family and section move into ThemeChoice. No panel keeps its own label map.

Scope

  • In: /shortcuts and /theme; the Slate-owned panel-focus.ts helpers for focus markers, fixed columns and tiny-screen priority; tests for both focus states, alignment at 100×30, 70×20 and 50×6, and width safety.
  • Kept: shortcut recording, conflict detection, press-twice removal, “Saved — applies when you close”, theme preview/restore, and all current keybindings.
  • Out: README and docs; new features; the /prompts search overlay and read-only inspector, which have no two-pane control surface.
  • Frame note: picker-frame.ts now owns the shared focus row. pi-web-search vendors a byte-identical copy and must resync its frame.ts and parity test before its next release.
