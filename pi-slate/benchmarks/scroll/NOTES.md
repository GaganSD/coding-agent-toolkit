# Fullscreen scroll benchmark notes

Run from `pi-slate/` with the usual package dependencies, Python 3.8+, Node.js supported by Pi, and Pi 1.6.0 installed globally (or set `PI_CLI` to its bundled `cli.js`). The live driver uses a macOS/Linux PTY; it does not measure Windows Terminal or any other terminal emulator. No credentials or model calls are needed.

```sh
npm run bench:scroll -- --capture  # default: large, five variants, both terminals, three runs each
npm run bench:scroll -- --size small --runs 1 --variants slate --terminals 120x40
npm run bench:scroll -- --size medium --runs 1 --variants slate --terminals 200x50 --stacks --cpu-prof
npm run bench:scroll -- --scenario busy --variants native slate slate-no-sidebar
npm run bench:scroll -- --compare old.json new.json
```

To include npm builds in the same suite, unpack and install them without adding them to the real Pi agent directory:

```sh
mkdir -p benchmarks/.cache/slate-0.4.0 benchmarks/.cache/starline
(
  cd benchmarks/.cache
  npm pack pi-slate@0.4.0 pi-starline@0.13.0
  tar -xzf pi-slate-0.4.0.tgz -C slate-0.4.0 --strip-components=1
  tar -xzf pi-starline-0.13.0.tgz -C starline --strip-components=1
  (cd slate-0.4.0 && npm install --omit=dev --ignore-scripts)
  (cd starline && npm install --omit=dev --ignore-scripts)
)
npm run bench:scroll -- --scenario busy --size large --runs 3 --allow-dropped-input \
  --slate-fresh --terminals 200x50 120x40 --variants native slate-0.4.0 slate starline \
  --extension-path slate-0.4.0 benchmarks/.cache/slate-0.4.0 \
  --extension-path starline benchmarks/.cache/starline
```

For the idle suite, use `--scenario idle --terminals 200x50`. `--extension-path VARIANT DIR` is repeatable and overrides the extension directory for a selected non-native variant. `results.json` records each loaded extension's path, manifest name/version and a SHA-256 fingerprint of its source and package files. `slate-0.4.0`, `slate-main-before`, and `starline` require explicit paths and are not part of the default matrix. Pi supplies Starline's Pi peer dependencies. Starline 0.13.0 runs with no config file or interaction in the isolated, non-Git workspace. It mounts its editor and footer but retains Pi's primary transcript ScrollView and full history. The probe attests its `PolishedEditor` and zero Slate surfaces. It uses the same wheel accounting as for native Pi, wrapping the live router after startup so Starline's editor-wheel patch remains active.

- The seeded Pi v3 JSONL has a linear history with tools, diffs, thinking, and occasional multi-screen Markdown answers. `small`, `medium`, and `large` mean 200, 1,000, and 3,000 entries after the header. Use `--entries N` and/or `--seed N` to customize it. The final heading stays short and visible. Every case gets the same history; the hash excludes the temporary path in the header.
- Pi gets a blank cwd and new home, agent, and session directories per run. The child `PATH` excludes the real agent directory, including directory symlinks into it. Pi 1.6 supports `PI_OFFLINE=1`; the driver also sets `PI_SKIP_VERSION_CHECK=1` and disables telemetry, discovery, and MCP. Missing `fd`/`rg` are not downloaded. Recorded tool calls are not executed. Pi is fullscreen with truecolor, a fixed theme, and `fullscreenWheelScrollLines: 1`.
- `slate`, `slate-0.4.0`, `slate-main-before`, and `slate-no-sidebar` use Slate's **shipped-default** `messageLength` (100 chat children at this revision), but explicitly enable the transcript surface. Pass `--slate-fresh` to leave `pi-slate.json` absent for `slate`, `slate-0.4.0`, and `slate-main-before`: the sidebar starts hidden in focused mode and the transcript window is off. The chat adapter still mounts to group tool cards, but full history is rendered. Results record observed `chat_adapter` and `chat_projection` separately from configured `transcript.owned` and `transcript.limit` (`shipped-default` or `all`). The transcript-window part of PR #151 is exercised with the default benchmark configuration, not `--slate-fresh`. `slate-matched-history` uses all surfaces and `messageLength: "all"`, matching the rendered history depth of native Pi. `slate-no-toolcards` disables both tool cards and transcript, so it also has no Slate history limit. The visible sidebar is in its full tier at `200x50` and compact at `120x40`.
- **First paint** measures time, process CPU, and PTY bytes from spawn through the first complete synchronized paint (which can precede the transcript and the probe). It has no probe frame counts or bytes/frame ratio. `--capture` saves the raw startup stream through the later complete synthetic transcript paint in mouse mode, first run per case. Startup is not a cold-cache measurement.
- **Readiness** requires the transcript paint, Pi 1.6's post-paint TUI invalidation after its bundled Markdown grammar preload, no outstanding Slate diff jobs started by Pi rendering, and 750 ms without a startup invalidation, forced request, or new/settling diff highlight. The probe counts constructed Slate diff views through the public tool-result renderer resolver, but only waits on existing jobs; it never starts highlighting itself. Regular sidebar ticks do not reset readiness. If Pi fails to settle within the bounded `--readiness-timeout` (30 s), the run fails.
- After readiness, the probe verifies the mounted Slate header/footer/editor, the visible sidebar layout box and `Symbol.for("pi-slate.sidebar-split")`, the chat container's Slate render/mouse overrides, and observed Slate diff views. A one-off warm render at the settled layout width counts which chat children actually render and rejects a mismatched history limit. It checks the same surfaces around both wheel bursts and takes fresh snapshots of the primary ScrollView’s `scrollTop` and maximum offset via `SIGUSR2` outside the measured windows. The transcript must start at the bottom and have at least 400 scrollable lines before idle or wheel measurements begin. The probe counts wheel lines that reach the primary ScrollView's `scrollBy` during Pi's wheel routing, including lines clipped at the boundary. The driver computes `dropped_wheel_lines` for each burst from those counts and reports `viewport_displacement_lines` separately. `max_scroll_top` is the maximum legal scroll offset (content height minus viewport height, in lines) at the end of the burst; the validation record includes both boundaries. A build that blocks for long frames can lose wheel input (Slate 0.3.0 with full history lost 1–4 of 400 events in some runs while the content height stayed constant); `--allow-dropped-input` records input shortfalls instead of failing. Changes to the scroll range during a burst are rejected regardless of that flag, including transient changes observed between snapshots. The scenarios are 5 s of idle, then 400 SGR wheel-up and 400 wheel-down events at column 40, row 20, with a nominal 5 ms between events and 1 s of settling per burst. PTY backpressure delays input rather than dropping it; the measured burst wall time includes these delays.
- `--scenario busy` keeps the same startup checks, idle sample and wheel bursts, but starts an offline model with hidden thinking just before wheel-up. At the start of wheel-down it finishes thinking, emits text and a `read` call against a synthetic local file, then streams a follow-up answer until the burst ends. The provider aims for a delta every 30 ms (~100 estimated tokens/s); a stalled event loop can slow it down. The driver releases thinking after the wheel-down measurement starts. It requires both thinking end and tool start inside that window, tool completion, and deltas in both directions. Busy runs allow scroll range changes between wheel events. For each delivered event, the probe checks the resulting offset against the movement allowed by the bounds at that instant. `--scenario idle` remains the default.
- The zero-height probe widget wraps Pi's **private** fullscreen TUI methods and reads `contentChanged` at `doRender` entry to distinguish content frames (no reuse of the prior transcript render cache) from view frames. This is Pi's cache decision, not a count of child components that actually recomputed. Frame durations use `performance.now()` and exclude input latency and terminal-emulator work. Baseline runs count content requests without collecting stacks; `--stacks` enables top caller attribution (`requestRender` or `requestImmediateRender`). Both requests and completed frames are assigned to phases by wall-clock timestamp. CPU (Linux `/proc`, macOS `ps`) and PTY byte attribution at boundaries are approximate. `p95` is nearest rank; each metric is medianed across repeats, ignoring missing values.
- `benchmarks/results/scroll-*/` contains `results.json` (medians, per-run metrics and attestations), `results.md` (separate startup and steady-state tables), and `summary.md` (path-free aggregates for sharing). All generated results are ignored. `--compare` matches terminal, variant, and history mode, and requires identical workloads and readiness-policy revisions. Both reports must use the current revision, identical extension paths/versions/fingerprints and the same `--slate-fresh` setting. To compare different extension builds, run them side by side with distinct variants and `--extension-path`. Diagnostic stacks and whole-process `--cpu-prof` data can contain local paths and add overhead; compare unprofiled, stack-free runs on the same hardware and Pi/Node builds.

Run the wheel-accounting regression tests with `python3 -m unittest discover -s benchmarks/scroll`. Set `SLATE_BENCH_TEST_PTY=1` to include a real Pi run with four omitted events in each burst.

The layout and readiness checks rely on Pi/Slate internals and intentionally fail rather than silently benchmarking the wrong renderer. Update the probe when those internals change. If a saturated run hits the PTY write deadline, try running the compact matched-history case first. This runs the same matrix in that order:

```sh
npm run bench:scroll -- --size large --capture --terminals 120x40 200x50 \
  --variants slate-matched-history native slate slate-no-sidebar slate-no-toolcards
```
