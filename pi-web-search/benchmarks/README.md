# Search wrapper benchmark

Run `npm ci --ignore-scripts --no-audit --no-fund` and `npm run research:offline` from the package directory. The runner writes JSON and Markdown to the ignored `research/results/` directory, and CI runs the same command. The versioned [baseline](results/baseline.md) records package commit `1c7ac9088d46630dca6c196a8334250adc55542f`. The wire fixtures are synthetic provider responses. This benchmark measures what the wrapper adds while holding provider evidence fixed. It does not measure provider ranking or factual answer quality.

## Tasks and replay

There are 20 calibration tasks and 20 held-out tasks. A benchmark contributor wrote calibration, and a separate contributor authored held-out prompts and tool expectations without the calibration set or model output. The cases cover public facts, docs, public code qualifiers, HTML, Markdown, PDF and GitHub URL extraction, multipart tasks and ref/cursor continuation. Each JSONL task identifies its expected call limit, ref use and numbered fixture evidence. The task files contain no answer keys.

The package's registered `search` tool runs in a temporary clean HOME with no operator auth or settings. The transport layer responds to fixture-matched HTTP requests and MCP JSON-RPC calls, and a process guard denies raw socket and datagram traffic. Every replay miss fails the suite with the destination host and path, even when package fallback catches the error. Fixtures contain only public inputs and synthetic evidence. A sanitizer check rejects credential-bearing fixture entries. The individual egress tallies count provider requests including MCP handshakes and cleanup; refs must make zero requests.

On Linux, an additional operating-system check is possible with `unshare --user --map-root-user --net npm run research:offline` where user network namespaces are enabled. On macOS, where Seatbelt profile execution is allowed, use `sandbox-exec -p '(version 1) (allow default) (deny network*)' npm run research:offline`.

## Metrics

| Suite | Measurement and gate |
| --- | --- |
| Context | Pi SDK builds the tool declaration and system prompt. Estimate tokens by rounding up characters divided by four. The declaration and prompt delta must fit 400 estimated tokens in 0.5.0 (380 in 0.4.0). Every baseline task stays within 5% of its estimated result-token count and evidence density. The footprint still requires eight previews and a result budget of 4,500 direct and 6,000 structured characters. |
| Evidence density | Characters of whitespace-normalized visible excerpts divided by characters of model-facing direct output. Duplicate rate counts repeated URL and excerpt pairs within a response. |
| Reliability | Fast must preserve evidence from the next provider on retryable failure. Thorough must retain all healthy sibling hits and identify the failed provider in a warning. The matrix covers provider timeout, 429 with both Retry-After forms and without it, 500, 502, malformed JSON, truncated bodies, open slow bodies, MCP disconnect and MCP session expiry. Production non-retryable fast outcomes are recorded in the JSON. |
| Deadline and cancellation | The 99th percentile across the fault matrix must stay within 250 ms of the configured 1,000 ms deadline. The active REST cancellation probe must settle within 100 ms and make no further requests. MCP may send a best-effort DELETE on teardown after a deadline, recorded against the originating case. |
| Citation | Each visible hit must link to an HTTP(S) URL from its fixture, and each visible snippet must be present in that source's evidence after whitespace normalization and removal of the presentation ellipsis. Ref and cursor reads must exactly match stored passage characters and offsets. |
| Safety | The suite rejects URL credentials and unsupported schemes before egress, checks credential redaction, and checks the provider allowlist per case. The frozen 0.4.0 corpus uses Jina extraction in both versions for stable context comparisons. The release suite gates private addresses, redirects, DNS revalidation and connection pinning in the actual local reader, on both Pi and MCP. Injection marker pass-through is measured before and after a deterministic classifier verdict. |
| Setup | A fresh, unconfigured first search must return evidence, and representative invalid configurations must provide actionable guidance. The packed entry point must load in a clean agent HOME using locally installed dependencies. `npm run pack:check` separately verifies an actual isolated npm install, and the benchmark files are excluded from the tarball. |
| Local reading | HTML, Markdown, PDF, and GitHub blob, PR and issue cases exercise the actual MIME and GitHub parsers using in-process response fixtures. Each path must preserve the requested URL and visible evidence; Jina is contacted only in the deliberately failing eligible public case. |
| Providers and efficiency | Gates three native filter mappings, unsupported recency warnings, Parallel objective and keyword routing, Brave Context, the configured SearXNG origin, Context7 version and lookup reuse, empty fallback, query-aware evidence and partial batches. |
| MCP | The stdio session exercises the same 40 corpus tasks and direct reader cases. Structured results must validate against Pi's output schema. The complete tools/list declaration, including annotations, must fit 110% of Pi's tool name, description and parameter declaration before its separate prompt delta. |
| Overhead | Model-facing tool wall time minus time spent generating replay responses, reported as p50 and p95. Also reports extension cold registration and process peak RSS in KiB. Machine timing and memory are advisory. |

A baseline refresh is deliberate. Run `npm run research:offline -- --initialize-baseline`, review the reports, and copy both into `benchmarks/results/`. Future changes run against that versioned baseline and report deltas. The report identifies the checked-out commit, so measure a committed package source tree when recording a release baseline.

## Optional research

- `npm run research:ergonomics -- --live --model=<provider>/<model> --model=<other-provider>/<model>` makes billed calls through Pi authentication. Each model runs three trials per task. The runner records first-call validity, recovery turns, consecutive repeated bad calls, tool calls and successful ref follow-ups. It reports approximate 95% intervals using each task's trial mean as an observation. Retrieval uses replay and provider keys are disabled. No live model baseline was collected for this offline baseline.
- `npm run research:record -- --live --task=cal-01` sends one versioned public query to keyless Exa with no Pi auth or provider-key inheritance. The normalized recording is saved to ignored `research/results/` for review. It excludes headers, account and request metadata, URL queries and fragments. Review all titles and excerpts for unexpected sensitive content before adapting them into fixtures.
- `npm run research:compare` loads the unmodified [pinned pi-web-access source](https://github.com/nicobailon/pi-web-access/tree/4427fb2044adcd176ced091dc82ff787f3b039ff) from `research/.cache/pi-web-access` or `PI_WEB_ACCESS_CLONE`. Prepare its dependencies separately and keep the checkout at `4427fb2044adcd176ced091dc82ff787f3b039ff`. The command compares the Pi SDK-built declaration and prompt budgets and writes `research/results/compare.md`. The competitor's retrieval and citation paths have no compatible replay adapter here, so there are no comparative agent or citation scores.

- Run `npm run research:urls -- --live` for a keyless live check of 30 public URLs. It reports local reads, Jina fallback reads, and failures as JSON.
- Run `npm run research:offtopic -- --check-fixtures` to validate the separate 30-case calibration and holdout sets. Run `npm run research:offtopic -- --live --model=<provider>/<model>` for 60 billed classifier calls on a pinned Pi model. It applies the calibration threshold to holdout and writes `research/offtopic.md`. The runtime fallback is gated on zero wrong off-topic judgments in holdout.
